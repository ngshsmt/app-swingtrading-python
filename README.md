# 仕様書: Pythonアラート_v1.0.0

## 背景と目的

- **背景:** TradingView（Essentialプラン）の仕様上、全監視銘柄×全シグナルに対して標準アラートを設定・維持するにはプラン制限（費用・枠数上限・複数条件監視の制約）が発生する。
- **目的:** 無料の外部自動化インフラ（Python / GitHub Actions）を活用し、大引け後に東証全対象銘柄の売買シグナルを全自動で判定・抽出する。抽出結果をNotionへ一括登録するとともに、メール通知・スプレッドシート連携（リスク管理シート）までをシームレスにつなぎ、手動の転記コストをゼロにする。

## 当該ツールで行う内容

1. 毎日15:35（東証大引け・データ確定後）にGitHub Actionsが定時起動。
2. CSVで管理された監視対象銘柄（JPX400）の日足データを `yfinance` 経由で取得。
3. `Supertrend`（10, 3.0）および 移動平均線（SMA 5, 10, 20, 50）のパーフェクトオーダー条件を判定。
4. シグナルが出た銘柄を **Notion データベース** に自動挿入（詳細確認・注文管理用）。
5. 指定フォーマット（買い/空売りエントリー・手仕舞いごとの銘柄コード一覧）で **Gmailメール通知** を送信。
6. Notionでステータスを「注文済」に変更した銘柄を、GAS経由で **Googleスプレッドシート（リスク管理シート）** へ自動転記。Notionとスプシの連携は手動 or 自動（1時間おき）
    

### フロー図

```
[監視銘柄リスト (watchlist.csv)]
       │
       ▼
[GitHub Actions (毎日15:35自動起動)]
       │
       ├── ① yfinanceで日足データ取得 & テクニカル計算 (Supertrend + SMA)
       ├── ② シグナル判定 (Long / Short / Exit L / Exit S)
       │
       ├───> 【通知】メール送信 (指定フォーマットの銘柄コード一覧)
       │
       ▼
[Notion データベース (シグナル管理)]
       │
       │  ※ユーザーが大引け後にNotion上でチャート確認・判断
       │  ※翌朝発注する銘柄のステータスを「注文済」に変更
       ▼
[Google Apps Script (GAS)]
       │
       ▼
[Googleスプレッドシート (リスク管理シート)]
       │
       └─> 小次郎講師流ATRユニット等に基づき「発注株数」「リスク金額」を自動算出
           ・元本、損失許容率、Supertrend下限バンド（ATR×3）から「発注株数」を自動算出
           ・総資金20%上限、1000万円キャップ、ポートフォリオ最大損失リスクを考慮して確認
```

## 機能要件

### 1. テクニカル計算・判定機能

- **計算指標:**
    - SMA 5, 10, 20, 50
    - Supertrend (Period: 10, Factor: 3.0)
- **シグナル判定ロジック:**
    - **買い環境 (パーフェクトオーダー):** `SMA5 > SMA10` AND `SMA10 > SMA20` AND `Close > SMA50`
    - **買いエントリー (`longEntryCond`):** `isStBuy`（Supertrend買い継続）AND パーフェクトオーダー AND (`Supertrend買い転換初日` OR `SMA5とSMA10のゴールデンクロス`)
    - **買い手仕舞い (`longExitCond`):** `SMA5 < SMA20`（デッドクロス） OR `not isStBuy`（Supertrend売り転換）
    - **空売り・空売り手仕舞い:** 将来拡張用枠組み（データ構造上保持）

### 2. Notion API連携機能

- シグナルが成立した銘柄のレコードをNotion DBへ新規作成。
- **プロパティ構成:**
    - `銘柄` (Title): 例 `4684 トレンドマイクロ`
    - `日付` (Date): 実行日（例 `2026-10-04`）
    - `シグナル` (Select): `Long` / `Exit L` / `Short` / `Exit S`
    - `終値` (Number): 当日大引け価格
    - `ステータス` (Select): 初期値 `未対応`（ユーザー操作により `注文済` / `転記済` へ更新）

### 3. メール通知機能 (Gmail SMTP)

- **件名フォーマット:** `yyyy/mm/dd(aaa)の対象銘柄コード`（例: `2026/10/04(日)の対象銘柄コード`）
- **本文フォーマット:**
```
①エントリー
【買い】
（銘柄コードのみ1行1コード）

【空売り】
（銘柄コードのみ1行1コード）

②手仕舞い
【買い】
（銘柄コードのみ1行1コード）

【空売り】
（銘柄コードのみ1行1コード）
```

### 4. スプレッドシート自動転記機能 (GAS)

- Notion DBのステータスが `注文済` に変更されたことをトリガーに、Googleスプレッドシート（リスク管理シート）へ `日付` `銘柄コード` `銘柄名` `想定エントリー価格（終値）` `損切り価格目安（Supertrend下限バンド）` を自動転記。
- スプレッドシート内の関数により、`ATRユニットによるポジションサイズ` および `単一建玉上限20%` / `1000万円キャップ` に基づいた発注株数を自動計算。

## 非機能要件

- **コスト:** 完全無料（GitHub Actions無料枠、Notion API、Gmail SMTP、GASを活用）。
- **実行タイミング:** 毎日 **15:35 JST**（東証取引時間終了・日足確定直後）。
- **セキュリティ・機密情報管理:**
    - APIキー、メールパスワード、Notion Database ID等の機密情報はすべて **GitHub Secrets** および **GASプロパティサービス** にて暗号化管理（コードへの直書き禁止）。

## 接続する外部ツール

1. **GitHub Actions:** 定時バックグラウンド実行インフラ
2. **Yahoo! Finance (`yfinance`):** 株価日足データの自動取得 API
3. **Notion API:** シグナル一覧のデータベース保存・管理
4. **Gmail (SMTP):** 銘柄コード一覧のメール自動送信
5. **Google Apps Script (GAS):** NotionとGoogleスプレッドシート間のリアルタイム連携
6. **Googleスプレッドシート:** リスク管理およびポジションサイズ（ATRユニット等）計算シート

# モンテカルロシミュレーション 設定パラメータ仕様書(v1.0.0(最新版はv1.4.0) 2026/09/25)

以下は、Pythonによるトレードデータのモンテカルロシミュレーション実行前に設定するパラメータ一覧です。運用方針に合わせて数値を変更してください。

---

## 1. 資金管理（ポジションサイジング）の設定
* **初期資金 (`initial_capital`)**
  * 設定値: `1,000,000` (円)
* **ポジションサイズ決定モデル (`position_sizing`)**
  * 設定値: `"atr_unit"`  
  * 選択肢:
    * `"fixed_amount"` : 固定金額指定 (例: 1銘柄につき〇〇円購入)
    * `"fixed_ratio"`  : 定率指定 (例: 総資金の〇〇%分購入)
    * `"fixed_risk"`   : 固定リスク率 (例: 損切り時に総資金の〇%の損失に収まるよう枚数調整)
    * `"atr_unit"`     : ATR / ボラティリティに応じたユニット調整
        * 認識のすり合わせのために言うと、「投資用資金×損失許容率[%]÷（ATR×倍率）」という数式で計算している。
        * 損失許容率は2.00%
* **1銘柄あたりの最大保有ポジション**
  * 設定値: 総資金（元本と最大許容レバレッジの積）の12.5%まで
* **最大許容レバレッジ (`max_leverage`)**
  * 設定値: `2.0` (倍) ※1.0 = 現物のみ、3.0 = 信用取引上限など
  

---

## 2. シミュレーション試行条件の設定
* **試行回数 (`num_simulations`)**
  * 設定値: `10,000` (回)
* **1試行あたりの試行トレード数 (`trades_per_simulation`)**
  * 設定値: `500` (トレード) ※全データから抽出する1回の検証用トレード数
* **サンプリング手法 (`sampling_method`)**
  * 設定値: `"bootstrap"`
  * 選択肢:
    * `"bootstrap"` : 復元抽出 (全6,662トレードからランダムに重複を許して抽出)
    * `"shuffle"`   : 非復元抽出 (全データの取引順序のみをランダムに入れ替え)
    * `"block"`     : ブロックブートストラップ (数トレードの塊ごとに抽出して連勝・連敗のクセを維持)
* **ブロックサイズ (`block_size`)**
  * 設定値: `5` (トレード) ※`block` 選択時に適用
* **乱数シード値 (`random_seed`)**
  * 設定値: `42` (再現性確保のためのシード値、不要な場合は `None`)

---

## 3. コスト・スリッページ・環境ストレステストの設定
* **スリッページ率 (`slippage_rate`)**
  * 設定値: `0.0005` (0.05% / 約定価格に対して不利な方向へシフト)
* **手数料倍率 (`fee_multiplier`)**
  * 設定値: `1.0` (倍) ※コスト増加のストレステスト時は `1.5` や `2.0` に変更
* **勝率補正パラメータ (`win_rate_modifier`)**
  * 設定値: `0.0` (0%調整) ※`-0.05` と設定すると勝ちトレード発生確率を意図的に5%ダウン
* **損益率倍率 (`return_multiplier`)**
  * 設定値: `1.0` (倍) ※利益縮小・損失拡大シナリオの検証時は `0.9` などに設定

---

## 4. リスク評価・終了条件（破産定義）の設定
* **撤退・破産判定ドローダウン率 (`ruin_drawdown_limit`)**
  * 設定値: `0.30` (30%) ※初期資金（またはピーク資産）から30%減少した時点でその試行を破綻と判定
* **完全破産閾値 (`ruin_capital_limit`)**
  * 設定値: `0` (円) ※資金が0円以下になった場合
* **集計・出力対象メトリクス (`metrics_to_output`)**
  * `["mdd_distribution", "ruin_probability", "final_capital_percentiles", "calmar_ratio"]`
    * `mdd_distribution` : 最大ドローダウン（MDD）の分布（平均, 95%ライン, 99%ライン）
    * `ruin_probability`  : 撤退・破産閾値に到達した確率 (%)
    * `final_capital_percentiles` : 最終資産の分位点 (5%, 25%, 50%, 75%, 95%)

---

## 5. 時間軸・並列保有（同時性）の制約設定
* **時間軸の扱い (`time_mode`)**
  * 設定値: `"trade_based"`
  * 選択肢:
    * `"trade_based"` : トレード単位 (日付や同時保有を無視し、1ステップ＝1取引として連続計算)
    * `"calendar_based"` : 時系列・カレンダー単位 (日付・保有期間・同時ポジション数の制約を厳密に再現)
* **資金拘束エラー時の挙動 (`funding_insufficient_action`)**
  * 設定値: `"skip"` ※`calendar_based` 選択時、余力不足で新規注文が出せない場合は「見送り (skip)」か「建玉縮小 (scale_down)」を選択

# `operations/app.py`（銘柄選定評価ダッシュボード / Streamlit）

## 1. 役割と境界線（単一責任）
- **責務**: Notion DB（全シグナル履歴）と Googleスプレッドシート（実運用ログ）を突き合わせ、銘柄選定の有効性（アルファ）を可視化・比較評価する。
- **制約**: `core/` 配下のテクニカル計算や売買判定ロジックは**一切使用しない**（独立した評価・可視化モジュール）[cite: 1, 4]。
- **実行環境**: Streamlit Community Cloud（メインファイルパス: `operations/app.py`）[cite: 1]。

## 2. データソースと結合・集計仕様（重要・変更厳禁）
1. **ベンチマーク（全シグナル: `df_bm`）**
   - **ソース**: Notion DB（ページネーション対応で全件取得）。
   - **構造**: 1日1行のイベントログ（`Long`/`Short` と `Exit L`/`Exit S`）を「銘柄コード + エントリー日付」基準でペアリングし、1トレード＝1行に集約する。
   - **価格・損益基準**: シグナル点灯日（前日）の終値基準。計算式は `((手仕舞い価格 - エントリー価格) / エントリー価格) * 100`（ショートは符号反転）。
2. **実運用データ（リスク管理シート: `df_user`）**
   - **ソース**: Googleスプレッドシート「シート1(GAS連携中)」（全19列レイアウト / A〜S列）。
   - **構造**: 1トレード（点灯〜消灯・実約定）が1行に集約済み[cite: 2]。
   - **参照カラム**: `エントリー点灯日付`(B列), `エントリー日`(C列), `消灯日付`(D列), `手仕舞い日`(E列), `銘柄コード`(F列), `売買方向`(H列), `想定エントリー価格`(L列), `エントリー価格`(M列), `損切り価格`(N列), `手仕舞い価格`(P列), `確定損益率[%]`(Q列)[cite: 2]。
   - **禁止事項**: スプレッドシート読み込み失敗時の例外処理において、ベンチマークデータ（`df_bm`）を丸ごとコピーして `df_user` にフォールバックさせる処理は**厳禁**（集計値が同一化するバグの原因）。
3. **未決済ポジションの扱い**
   - 手仕舞い未確定（空欄）のレコードも「トレード回数」の母数には含めるが、損益率や個別ログ表示は「保有中(未決済)」として統一し、確定損益の集計からは除外する。

## 3. UI・デザイン規約（Invariants）
- **スタイル**: 高密度エンタープライズUI（角丸 `border-radius: 0px !important`、フォント `BIZ UDGothic`、最小フォントサイズ `16px` 基準、数値は等幅フォント）。
- **カラーコード**:
  - ヘッダー背景: `#1e293b` / タイトル文字: `#ffffff`
  - メインアクセント・プラス表記・ソリッドボタン: `#059669`
  - マイナス表記: `#dc2626`
- **期間選択UI**: ソリッド長方形ボタン（直近1ヶ月 / 直近3ヶ月 / 今年 / 全期間）。データ保有期間がボタンの対象日数に満たない場合は `disabled=True` かつ `opacity: 0.4` で無効化し、`StreamlitValueBelowMinError` を防止する。
- **セクション見出し**: チャートタイトル（「■ 累積損益率推移 (%)」等）も含め、すべて `.section-header`（18px / 太字 / 左ボーダー `#059669`）で統一する。
- **個別トレードログ**: Notion DB のステータスに基づき、各シグナルの「判定（採用 / 見送り）」カラムを必ず表示する。
